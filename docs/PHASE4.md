# Phase 4 결과: 하이라이트

2026-11-02

## 결정 (Phase 시작 시 사용자 선택)

- 불투명도: 슬라이더로 조정, 10~100%, 10% 단위, 기본 40%
- 모양: 줄마다 평평한 직사각형 (앱이 AP를 직접 생성)
- 기본 색: 청록 `[0.219604 0.898041 1]`

## 구현한 것

| 영역 | 내용 |
|---|---|
| 엔진 `src/pdf/engine/highlight.ts` | 읽기: QuadPoints를 user space에서 page space로 바꿈(회전 쪽 포함). /C는 gray, RGB, CMYK를 읽고, /CA가 없으면 1. 쓰기: annot dict와 AP를 raw 객체로 씀(`/F 4`, `/NM`, `/C`, `/CA`, `/QuadPoints`, `/Rect`, `/M`). 고칠 때는 같은 annot 객체에 AP만 새로 씀. 지우기: /Popup도 함께 지움. `PdfEditor.highlights()`, `putHighlight()`, `deleteHighlight()` |
| AP | 바깥 Form이 ExtGState(`/BM /Multiply`, `/CA`, `/ca`)로 안쪽 transparency group Form을 그림. 안쪽 Form은 quad마다 평평한 사각형을 채움. 그래서 줄끼리 겹치는 곳도 한 번만 칠해지고, 하이라이트 전체가 한 불투명도로 합성됨 |
| 글자 선택 | worker의 `selectText`: 드래그는 `StructuredText.highlight(from, to)`, 더블클릭은 `snap(p, p, "words")`. 시작점이 글자 줄 bbox 밖이면 빈 결과(빈 곳, 스캔본). 쪽별 StructuredText 캐시 |
| 하이라이트 도구 (H) | 드래그하는 동안 기본 색으로 미리보기를 그림(worker 요청은 한 번에 하나, 마지막 위치 우선). 놓으면 확정됨. 여러 줄이면 주석 1개에 줄별 quad. 더블클릭은 단어(이미 하이라이트된 곳을 더블클릭하면 선택만 함). 그냥 클릭하면 하이라이트 선택/해제. 이 도구에서는 텍스트 상자가 마우스를 가로채지 않음 |
| 선택 도구 (V), 텍스트 도구 (T) | 선택 도구에서 하이라이트를 클릭하면 선택됨(텍스트 상자가 위에 있으면 상자가 우선). 텍스트 도구에서는 하이라이트 위를 클릭해도 새 상자를 시작함 |
| 팝오버 | 선택한 하이라이트 위에 뜸: 색 5개(청록, 노랑, 연두, 분홍, 주황) + 색상 선택기, 불투명도 슬라이더, 삭제. Delete/Backspace로 삭제, Esc로 해제. 하이라이트 도구에서는 툴바에도 붙어 있고, 선택한 하이라이트가 없으면 도구 기본값을 바꿈(기억됨). 노랑은 Acrobat 하이라이트의 /C 값 |
| 표시 | base 비트맵에서 하이라이트를 모두 숨기고(`HIDDEN.highlights`), overlay(`src/annot/HighlightLayer.tsx`)에서 하이라이트마다 SVG 하나를 `mix-blend-mode: multiply` + `opacity`로 그림(AP와 같은 합성 방식) |
| Undo/redo | `DocStore`를 일반화해서 텍스트 상자와 하이라이트가 한 스택을 씀. 만들기, 색, 불투명도, 삭제가 각각 한 단계이고, 슬라이더를 끄는 동안의 변경은 한 단계로 합침 |
| 선택 | 텍스트 상자와 하이라이트 중 하나만 선택됨. 쪽을 넘기면 하이라이트 선택은 풀림 |
| import | 다른 프로그램이 만든 하이라이트도 읽어서 색, 불투명도 변경과 삭제가 가능함. `/NM`이 없으면 `obj:<객체 번호>`로 식별 |

PDFObject를 다루다가 생긴 문제도 고쳤음: 없는 키에 `.get("AP").get("N")`처럼 이어 부르면 예외가 나서, 엔진 전체를 경로 형식 `get("AP", "N")`으로 바꿈. PDF real이 float32로 돌아오는 문제(0.4 → 0.4000000059604645)는 모델로 읽을 때 반올림해서 처리함.

## 검증

- **단위 테스트 55개**: 엔진 19(하이라이트 5: 생성 후 다시 읽기, Multiply와 불투명도의 실제 픽셀 색, 회전 쪽, 같은 객체에서 색·불투명도 변경, 다른 프로그램 하이라이트 import 후 popup과 함께 삭제, /NM 없는 하이라이트), DocStore 13(텍스트 상자와 같은 undo 스택, 슬라이더 끌기가 한 단계), 뷰어 15, 스타일 4, 하이라이트 helper 4
- **실제 앱** (`tools/highlight-test.mjs` + `run-app.ps1`, DevTools 프로토콜로 실제 마우스·키 입력):

  - 2~4줄을 드래그하면 quad 3개짜리 하이라이트 1개
  - 빈 곳에서 드래그하면 아무것도 생기지 않음
  - 단어를 더블클릭하면 그 단어만(quad 1개). 이미 하이라이트된 단어를 더블클릭하면 선택만 함
  - 클릭 → 팝오버에서 노랑, 70% → Delete → Ctrl+Z로 노랑 70% 그대로 복원
  - 선택 도구로 클릭하면 선택되고 Esc로 해제. 텍스트 도구로 하이라이트 위를 클릭하면 상자 편집 시작
  - 회전(/Rotate 90) 쪽에서 드래그해서 생성
  - 3초 뒤 자동 저장

## 알려진 한계

- 팝오버는 하이라이트 바로 위에 떠서 윗줄을 가릴 수 있음. 하이라이트가 선택된 동안 그 자리에서 새 드래그를 시작하려면 먼저 Esc나 다른 곳 클릭으로 선택을 풀어야 함
- 다른 프로그램이 만든 하이라이트도 앱 화면에서는 평평한 사각형으로 보임(원래 AP 모양이 달라도). 파일의 AP는 앱에서 색이나 불투명도를 바꿀 때만 앱 AP로 바뀜
- 서로 다른 하이라이트가 겹치면 Multiply로 진해짐(Acrobat과 같음)
- 삭제를 되돌린 하이라이트는 겹침 순서상 맨 위로 옴(텍스트 상자와 같음)
- 이미 있는 하이라이트의 범위를 늘리거나 줄이는 기능은 없음(지우고 다시 칠함)
